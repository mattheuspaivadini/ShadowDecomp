// Symbol addresses for Shadow of the Colossus (USA), main ELF: SCUS_974.72
//
// Format: <name> = 0x<address>;
// NOTE: splat parses everything after the ";" on an assignment line as
// space-separated `attr:value` pairs, so assignment lines below end at the ";"
// and all explanation lives on its own "//" line above. Do not add text (or a
// colon) after the semicolon.
//
// Conventions: func_XXXXXXXX for functions, D_XXXXXXXX for data. Evidence only.
// The retail ELF is STRIPPED (no .symtab). Addresses below are confirmed from
// the ELF header / string evidence. See docs/analysis.md.
//
// Evidence classes used by the Phase-5 naming pass (Session 4, step 4); the full
// candidate table is docs/naming-candidates.md and the generator is
// tools/name_from_strings.py:
//
//   * "verbatim" - the function's own diagnostic message contains the routine's
//     identifier (log prefix "<name>:", e.g. "sceDbcSendData2: rpc error"), or
//     the name is passed as that message's own %s argument. Direct evidence.
//   * "object"   - the string is a semaphore/thread name the routine hands to
//     the kernel create call (e.g. "SceStdioReadSema"). It names the *object*;
//     the routine name is inferred from it, so it is marked UNCONFIRMED.
//   * UNCONFIRMED - identifier inferred from the evidence, not literally stated
//     by it. See docs/naming-candidates.md for the per-entry reason.

// ---------------------------------------------------------------------------
// Phase 5 (Session 4, step 4): "verbatim" self-naming log evidence.

// ---------------------------------------------------------------------------
// "ldsys: LoaderSysLoadIopModuleFromEEBuffer: iop identifier <name> exists at

// "ldsys: setNewIopIdentifier: set new iop identifier <name> at #N".
